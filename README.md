# 光速镜像 · GitHub 下载加速器

只用国内镜像下载 GitHub 文件：粘贴链接 → 逐个测速 → 只走最快的那条链路下载，**多个文件可以并发下载**（1–10 个可调），**单个文件默认再切 10 段多连接并行拉**，每个任务独立暂停 / 取消 / 计时。下完直接安装 APK，或把任何文件交给别的应用打开。另带一个**版本追踪**页：盯住项目的最新 release，只下你要的格式，安卓端默认只看 `arm64-v8a`；挑文件时可选**单个下载**（点一个就走）或**批量勾选**（勾完一次性并发开跑），下过的、在队列里的都会标出来。

### 怎么构建

```bash
./build.sh          # 安卓 APK + Rust 桌面 exe，产物都落到 release/
./build.sh apk      # 只出 APK（需要 ANDROID_HOME 指向 Android SDK）
./build.sh exe      # 只出 Rust 桌面 exe（需要 Node.js 20+ 与 Rust）
./build.sh py       # 只出 Python 桌面 exe（需要 Python 3 + PyInstaller）
```

Windows 上直接双击 `build.bat`（不带参数等于 `all`，没配 Android SDK 时会自动只构建桌面 exe）。

版本号只在一处维护：安卓读 `app-source/AndroidManifest.xml` 的 `versionName`，
Rust 读 `rust/src-tauri/tauri.conf.json` 的 `version`，Python 读 `desktop/lightmirror.py` 的 `APP_VERSION`。
打 tag（如 `v3.0.0`）会触发 GitHub Actions，自动构建并发布三个成品。

## 一、三套主题

| 主题 | 底色 | 主色 | 适用 |
| --- | --- | --- | --- |
| **深空**（深色） | `#0B0F14` | 电光青绿 `#2BE3A7` | 夜间、OLED |
| **纸白**（浅色） | `#F8FAFC` / 卡片 `#FFFFFF` | 墨绿 `#0A8F63` | 白天、普通手机默认 |
| **黑白**（墨水屏） | 纯白 `#FFFFFF` | 纯黑 `#000000` | 4:3 墨水屏 |

设置页「显示主题」四段：**自动 / 深色 / 浅色 / 黑白**。自动模式规则：

- 4:3 且短边 dp ≤ 640 → 黑白
- 4:3 但 density 报得离谱（有些墨水屏 ROM 报 160/240）→ 用「物理对角线 5–8.5 寸 + 短边 ≤ 1600px」兜底判定
- 其他设备 → **浅色**

三套主题共用一套布局与 drawable，颜色全部走语义属性（`?attr/cText` / `?attr/cBg`…），字号走 `?attr/dT0…dT5`，没有复制三份界面。

## 二、墨水屏专门适配（1072×1448 / 300dpi / 6 寸）

这台机器换算下来是 **572×772dp**（300dpi、6 寸、比值 1.351）。黑白模式下额外做了这些：

| 项 | 处理 | 原因 |
| --- | --- | --- |
| 字号 | 全部 +2sp：说明字 11→13、正文 14→16、标题 21→23、主数值 26→30 | 300dpi 上小于 13sp 的中文会发虚 |
| 按钮 | 44dp → 48dp | 手指点得准，也不需要放大图标 |
| 进度条 | 6dp → 10dp，加黑框 | 1~2% 的进度在墨水屏上要看得见 |
| 描边 | 全部实色黑，无半透明、无阴影 | 半透明在灰阶上会变成脏灰 |
| 渐变 | 卡片、头像、进度条全部改实色 | 墨水屏把渐变渲染成色带 |
| 波形 | 隐藏 | 每帧重绘必留残影 |
| 刷新 | 进度节流 1.1 秒/次（只在整数百分比变化时刷） | 减少整屏刷新残留 |
| 动画 | 关闭 Activity 切换动画 | 切页闪白 |
| 字体 | 文件名、速度、时间用等宽 | 数字跳变时不会左右抖 |
| 底栏 | 64dp → 68dp，字号 11sp | 五个页签挤在 572dp 里还要看得清 |
| 禁用态 | 不用 `alpha`，改白底黑框 | 灰度淡出在墨水屏上等于消失 |

## 三、版本追踪（新增页签）

底部第二个页签「版本」。三条路径都能进来：

1. 直接填 `owner/repo`、`https://github.com/owner/repo`、`.../releases` 任意一种地址
2. 首页粘贴**仓库地址**后点「测速并下载」→ 自动切到版本页并开始检查
3. 剪贴板里有仓库地址时，首页会自动填好

规则：

- 大范围在**设置 → 追踪格式**里统一勾选（多选，可加自定义扩展名、可删除），手机端默认 APK / ZIP / RAR / PDF
- 每个项目右上角的格式字样可以单独改（多选，只影响这个项目），**只列出这个项目最新版真实存在的格式**；项目没发 RAR，菜单里就没有 RAR
- 自动比对：没下过 → **「发现 v1.2.3 · 可以下载」**；下过且同版本 → **「已是最新」**；版本变了 → **「有新版本 v1.2.0 → v1.3.0」**
- 点「查看版本」列出该仓库最近 15 个 release（含预发布标记与日期），可以任选一个版本下载
- 已下载过的文件名在版本弹层里标灰，按钮变成「再下」
- 下载完成后自动回填「已下到哪个 tag」，下次进来就不会重复提示

### 标签：格式 + 差异，选中一个就只下它（1.9.0 新增）

手机端只列 **APK / ZIP / PDF / RAR**。同一个版本里同格式有多个文件时，会自动算出它们的差异，拼成「差异 · 格式」的标签：

| 文件 | 标签 |
| --- | --- |
| `…-android-arm64-v8a.apk` | ARM64 · APK |
| `…-android-armeabi-v7a.apk` | ARMv7 · APK |
| `…-android-universal.apk` | 通用 · APK |
| `…-android-x86_64.apk` | x86_64 · APK |
| `…-windows-x64-portable.exe` | 便携版 · EXE |
| `…-windows-x64-setup.exe` | 安装版 · EXE |

- 做法是逐字比对：先剥掉所有文件共有的产品名，再剥掉版本号和架构，剩下的就是真正不同的部分；同一格式内单独再算一次，所以不同格式不会互相干扰。
- 没有的格式不会出现对应标签；标签个数随项目和格式变化。
- 标签**可多选**：点一下选中、再点一下取消，选中几个就只看这几个；选中后「下载最新」在选中的范围里挑文件。点「全部标签 N」摊开继续加选，全部取消就回到全部文件。
- 标签名始终单行，太长自动缩小字号；文件名最多两行、再放不下继续缩，不会截成「… · AP」这种半截样子。

### 挑文件：单个 / 批量两种模式

开关在**设置 → 版本页**里，是一个左右可点、也能按住拖的滑块；版本弹层自己不再放这条，
但滑块停在哪一侧，弹层就按哪种方式工作。选一次就记住，重启、换项目、换架构都不会自己变回去。

| 模式 | 交互 | 适合 |
| --- | --- | --- |
| **单个下载**（默认） | 点一行 → 立刻测速 → 回首页开下，弹层自动关 | 只要一个包 |
| **批量勾选** | 每行前面出现方框，勾选只是进待下清单；底部按钮实时显示「测速并下载 N 个」，点了才统一测一次速、按并发数同时开跑 | 一次要下好几个版本/架构 |

批量模式下的三种状态一眼能分清：

- **已下载**：这个文件之前下完过（按 URL + 文件名双判定）。点它仍可勾选，但会先弹确认，说明会另存为「名字 (2)」，不会覆盖；
- **队列中**：已经在待下清单或引擎里，行变暗、不能再勾，点了只提示「已经在下载队列里了」；
- **已勾选**：方框打勾 + 主色描边，底部按钮计数 +1。

提交时还会再按 URL 去重一次（`BatchPlanner`）：重复的跳过、队列装不下的单独计数，提示语写成
「已加入 5 个文件 · 跳过 2 个重复 · 队列满，少了 1 个」，不会静默丢文件。

接口是 GitHub 公开 REST（未登录 60 次/小时），只在进入本页时请求，串行 + 间隔 200ms，失败会显示具体原因（404 仓库不存在 / 403 限流 / 网络不可达）。

## 四、下载与安装

- 进度条 + 百分比 + **已用时间**（自动扣除暂停）+ **预计剩余**（按本次任务平均速度算）
- 完成后出现 **安装**（APK）/ **打开**（其他类型）+ **其他应用打开**；记录页点任意一条也能打开
- 通过应用内只读 `ContentProvider`（`exported=false`，做了路径越级校验）以 `content://` 授权，不依赖文件管理器
- **保存位置可选**（设置 → 下载 → 保存位置，整行可点）：
  - 系统「下载」目录 `/Download/LightMirror/`：其它应用、文件管理器都能看到，**推荐**
  - 应用私有目录 `Android/data/com.lightmirror.dl/files/Download/`：免权限，卸载即清理
  - 自定义路径：直接填绝对路径，建不了或不可写会当场提示
- 写公共目录的权限：Android 11+ 走「所有文件访问」（`MANAGE_EXTERNAL_STORAGE`，设置里一键跳转授权）；
  Android 10 及以下走 `WRITE_EXTERNAL_STORAGE` 运行时申请。没授权或选的位置不可写时，
  自动回退到应用私有目录并提示，不会下到一半才失败
- APK 安装前会检查「安装未知应用」权限，没给就直接跳设置页，不会点了没反应

### 下载记录

记录页（底部第三个 tab）会给每个完成 / 失败 / 取消的任务留一条，只存本机。

- **右上「选择」进多选**：每行前面出现方框，勾选后底部浮出「全选 / 删除选中 N 条」；
  长按任意一条也能直接进多选并顺手勾上它，不用先点「选择」
- **删除分两种**：确认框里选「只删记录」（文件留在原处）或「记录和文件一起删」
  （按记录文件名去候选下载目录找，找到才删；删不掉会提示「可能被其它应用占用」）
- **右上垃圾桶 = 清空全部**，同样问一次要不要连文件一起删
- **显示条数可调**：默认 20 条，范围 5~200，记录页点副标题或设置 → 记录都能改；
  调小只是不再显示，记录本身还在，调回来还能看见。超出上限时列表底部会写明「还有 N 条更早的记录没显示」

存储侧最多保留 500 条（`HARD_MAX`），按时间倒序，超出丢最老的；显示上限与存储上限是分开的两件事，
所以把显示条数从 100 调到 10 不会真删掉 90 条记录。

## 五、镜像、测速与并发下载

**两种拼接方式**（实测 `xget` 只认路径式，完整链接式会返回 404）：

| 方式 | 例子 | 结果 |
| --- | --- | --- |
| 拼完整链接（默认） | `https://ghfast.top/` | `https://ghfast.top/https://github.com/owner/repo/...` |
| 拼 GitHub 路径 | `https://xget.xi-xu.me/gh/` | `https://xget.xi-xu.me/gh/owner/repo/releases/...` |

内置镜像新增 **`xget.xi-xu.me/gh`**（路径式，实测 256KB 探测首字节 1.3s，`ghfast.top` 为 2.3s，
两者都返回 206 支持 Range）。老版本升级会自动补进目录；用户主动删过的不会自动冒回来。

**镜像管理页**：**按住 ≡ 手柄上下拖动排序**（跟手、其余行实时让位、拖到边缘自动滚动）、
开关、删除（带确认）、恢复内置、自定义镜像可选拼接方式。
每行显示最近一次测速成绩或「连续失败 N 次 · 建议删除」。顺序即测速顺序，得分相同时靠前的优先。

**测速**：逐个镜像发 `Range: bytes=0-<分片-1>`，量首字节时间 + 分片吞吐，单镜像超时兜底，串行；
评分 = 速度 70%（12 MB/s 满分）+ 延迟 30%，首字节 >2.5s 打 5 折、>4.5s 打 4 折。
分片默认 256 KB，可在设置页改成 32~4096 KB；单镜像超时默认 8 秒，可改成 3~60 秒。
排名默认复用 10 分钟，可改成 1~720 分钟，也可以直接关掉「复用测速结果」每次都重测。

**两级并发**：

| 层级 | 默认 | 可调范围 | 说明 |
| --- | --- | --- | --- |
| 多文件同时下 | 3 个 | 1~10 个，任意数字直接输入 | `ThreadPoolExecutor` 任务表，共用一份镜像排名 |
| 单文件多连接 | 10 段 | 1~10 段，或整体关闭 | 按 Range 切片，每段一条连接，下完按序拼回 |

分段前先用 `Range: bytes=0-0` 探一次总大小和是否支持 Range；镜像回 200（不支持分段）或文件小于
2 MB 时自动退回单连接，不会下坏文件。分片保存在 `<文件名>.part.parts/`，暂停、换镜像、杀进程后
都能按段续传；全部到齐才拼成 `.part` 再改名，校验大小不符会直接判失败重来。

每个任务有独立的状态、进度、已用 / 剩余时间、暂停 / 取消，卡片副标题会写明
「via 镜像 · 10 线程」；同名文件自动加 `(2)` 后缀避免互相覆盖；失败按排名顺延最多 3 个。
首页任务列表支持「清除已完成」「全部取消」，完成后每张卡片单独给「安装 / 打开」。

## 六、修复记录

> 同一份内容另有独立文件 `CHANGELOG.md`，只想看改动历史的话直接翻那个。

### 2.0.6（安卓）：翻页加载更早版本时不再跳回顶部

- 现象：版本列表往下滑，触发「正在加载更早的版本…」，翻页回来后列表一下弹回最上面，得重新滑。
- 原因：`loadAllVersions` 拿到全量数据后直接调用 `openVersions(w)` **重建整个弹窗**，新 ScrollView 的 `scrollY` 从 0 开始，位置就丢了。
- 修法：只要翻回来的列表是当前列表的延续（逐条比对 tag 前缀一致），就把新版本**原地续铺**到现有容器末尾，不重建、不 `scrollTo`，滚动位置完全不动；每帧铺 50 条，几百个版本也不卡。
- 只有列表结构真的变了（加载期间仓库发了新版、插入到最前）才重建，重建时把当前 `scrollY` 带过去，不会再回顶。
- 顺带修掉一个隐藏问题：自动翻页原来在弹窗 `show()` 之前就发请求，回调若早于窗口创建会被丢弃，导致「正在加载更早的版本…」永远点不动。现在改到弹窗显示后再触发。
- 加载失败时那行提示变成「加载更早的版本失败，点这里重试」，可以直接重试。

### 2.0.5（安卓）：标签选中态跨版本对齐

- 现象：在版本列表里点选一枚标签后，往下滑，有些版本的同一枚标签是亮的，有些是暗的；按住不放还会连带影响「只看这几个」的筛选。
- 原因：标签的选中状态存的是 `vkey`——**文件名指纹**。而指纹会把版本号抹成 `*`，却不抹「`android-arm64-v8a`」和「`app-universal-arm64-v8a-release`」这种结构差异。同一个仓库不同版本换过打包方式，指纹就不同，于是同一枚「ARM64 · APK」在别的版本里命不中。
- 修法：新增**语义键** `labelKey`＝`标签名|格式`（去掉同格式撞车补的 `#2`），跨版本稳定。选中判定、筛选、去重全部改用它；老数据里存的指纹在打开版本列表时自动迁移成语义键，一次写完不再回退。
- 顺带：取消选中时会把散落在各版本里的同类旧指纹一并清掉，不会再出现「点了取消还亮着」。
- 顺带：某个版本里一枚选中标签都不存在时（老版本少文件），整条标签行不再占位，不留空白。
- 同一版本内若两个文件的标签完全相同，按语义键合并成一枚（以前会并排出现两个一模一样的 chip）。

### 2.0.4（安卓）：版本号整串显示，标签与时间同一行

- 2.0.2 用 TextView 的 autoSize（在 `singleLine` 下不生效，字号没变、直接成省略号）；2.0.3 改成布局完成后 `setTextSize`（被 ViewRootImpl 当成「布局中请求重新布局」吞掉，界面同样没变化）。两次都失败在**改字号的时机**上。
- 这次不再依赖 TextView：新增 `FitLabel`（自绘 View），在 `onMeasure` 里拿到真实可用宽度后选字号，`onDraw` 直接 `drawText`，量多少画多少。宽度不够就每 0.5px 降一档，**没有字号下限**，缩到放得下为止；地方够大就用原始 14sp。不折行、不加省略号。
- 版本号与右侧时间保持同一行：标签占满剩余宽度，缩完字号后与时间之间只留 6dp 间距，不会再出现「截断 + 一大段空白」。
- 弹窗标题（仓库名）同样改用 `FitLabel`，一行放不下就缩字号，不再折成两三行。
- 文件选择弹层的副标题（`tag · N 个文件 · 当前架构`）一并换成自绘标签，同样一行到底。

### 2.0.3（安卓）：版本号标签真正做成一整行

- 2.0.2 想用 `setAutoSizeTextTypeUniformWithConfiguration` 让 tag 缩字号，但它在 `singleLine + ellipsize` 的组合下不生效：字号仍是 14sp，直接变成了「`unsigned-v2026.11.9-3…`」。

### 1.8.1：修掉「部分设备点安装提示解析程序包出错」

- **根因**：文件提供者把 content:// 的路径写成 `dl/文件名`，取文件时又固定到
  「应用私有下载目录」去拼。可默认保存位置是「系统下载 / LightMirror」，
  于是安装器 `openFile` 直接拿到 `FileNotFoundException`，界面上只剩一句
  「解析程序包时出现问题」；文件管理器走的是真实路径，同一份文件当然装得上。
  只有授予了「所有文件访问」的设备才会落到公共目录，所以是「部分设备」。
- **修法**：URI 改成带**完整路径**（base64url 编码），按真实路径取文件；
  白名单放开到所有存储卷、应用各目录和自定义保存位置，仍然拒绝下载目录之外的文件。
  顺带解决同名不同目录串包的问题——以前两个同名的包会拿到同一个 URI。
- **安装这一步加固**：给所有能接手的应用显式 `grantUriPermission`，并同时挂 ClipData
  （个别 ROM 的安装器只认后者）；文件不存在、长度为 0、或 APK 头不是 zip 时先行拦下。
- **镜像把限流页存成 .apk** 的情况，以前只会看到系统那句解析失败，现在会明确说
  「这个文件不是安装包」，并提示重下或换镜像。
- **记录页点一行**改用和删除时同一套多目录查找，换过保存位置的旧文件也能点开，
  不再误报「文件已被清理」。
- 验证：72 个用例通过。新增 6 个，覆盖公共下载目录取文件、同名不同目录、
  白名单外拒读、中文显示名、记录页跨目录打开，以及 HTML 冒充 APK 的拦截。

### 1.2.3：检查更新频率修正

- 自动检查规则：**进入「版本」页才检查**（绝不后台偷跑流量），同一项目 **10 分钟内不重复请求**。
  1.2.2 有个 bug：节流时间戳只在下载完成时回填，接口拉取成功不记时间，导致每次切到版本页
  都会对所有项目重新请求——频繁切页会白白吃掉 GitHub 匿名接口 60 次/小时的配额。已在拉取成功
  时回填时间戳（`WatchStore.markChecked`）。
- 「追踪列表」标题行新增**「检查更新」**按钮：不看缓存、立即重查所有项目，想刷新时不用等 10 分钟。
- 追踪 N 个项目时的配额消耗：自动检查最多每 10 分钟一轮，即每小时最多 6N 次请求；
  一般追踪 5 个以内 + 偶尔打开看看，配额绑绑有余余。

### 1.2.2：版本排序 + 只下 arm64-v8a

以 `POf-L/Fanqie-novel-Downloader` 为例实测发现两类问题：

1. **版本排列乱**：GitHub 接口返回顺序不可靠——这个仓库所有 release 的 `created_at`
   完全相同（批量建好后逐个发布），接口顺序毫无规律，1.2.1 直接照单显示就乱了。
   修复：显式按 `published_at` 倒序重排；发布时间撞车时再用 tag 里的数字段倒序兜底
   （`r785` > `r783`，且 `v10` 不会再排在 `v2` 前面）。
2. **一个 release 塞十几个文件，不知道下哪个**：
   - 安卓端默认**只看 `arm64-v8a`**：列表里就剩这一个能装的包，`ABIS.txt`、sig、
     Windows/macOS 的产物统统不出现；该架构缺失时才回退显示全部
   - 手动换过一次架构（在选择框点 chip 或点某个文件），**这个项目以后都按它找**，
     偏好存在 `WatchStore` 里，卡片状态行会写明「推荐 arm64-v8a」

「查看版本」弹窗顶部有架构筛选条（arm64-v8a / armeabi-v7a / 通用包 / x86_64 / 全部），
每个版本只铺一行推荐文件，其余收进「共 N 个安装包 · 换架构」的选择框。

验证：用该仓库真实 release 数据在 JVM 上跑了 6 个排序/筛选用例 + 7 个启动冒烟用例，全部通过。
